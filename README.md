# DRONK

**Drone Reconnaissance & Observation Network.** A passive receiver for drone Remote ID broadcasts, built around the ESP32-C5, that turns what it hears into TAK-compatible map data.

> [!IMPORTANT]
> DRONK is in active development. On 2026-11-02 it completed its first end-to-end field test: a real drone's Remote ID broadcast was received, decoded, forwarded to a TAK Server and displayed in iTAK. Several features, including the LAST KNOWN marker lifecycle and the new map symbols, are tested in software only. See [Status](#status).

## What it does

Most drones flying in the US are required to broadcast Remote ID: a short, public radio message carrying the aircraft's identity, position, altitude, speed, and the operator's or take-off location.

DRONK:

1. **Receives** those broadcasts passively over Wi-Fi, using an ESP32-C5 receiver.
2. **Decodes** them on a Linux host, from one or more receivers.
3. **Records** every raw receiver line in an append-only capture and indexes it in a local SQLite history, including when the receiver was actually listening.
4. **Generates** Cursor-on-Target (CoT) messages, with separate markers for the aircraft and for the operator or take-off position when the broadcast includes them.
5. **Forwards** them to a TAK Server over mutual TLS, only when LIVE mode is chosen explicitly.

The aircraft data in each message (identity, position, altitude, speed) comes from the broadcast. Everything else that a TAK message needs, such as the marker type, timestamps and how long the marker stays valid, is generated by DRONK.

## Passive by design

DRONK only listens.

- It does not transmit to, interfere with, jam, spoof or take control of any aircraft.
- The receiver scans Wi-Fi channels passively on 2.4 GHz and 5 GHz. It doesn't join networks or send probes.
- DRONK doesn't invent aircraft data. If a value wasn't in the broadcast, it isn't presented as if it were. A drone heard without a valid position is shown as detected, never placed on the map.

Remote ID is a public broadcast intended to be received. Even so, check your local rules before deploying any RF receiver, and treat captured operator locations as personal data.

## Status

**Field-verified** means it was run with a real aircraft, real receiver and real TAK client. **Software only** means it is implemented and covered by automated tests, but has not been checked against real hardware or a TAK client.

| Capability | Status | Evidence |
|---|---|---|
| ESP32-C5 receiver, dual-band channel scanning (20 US channels) | Field-verified | about 12 h soak: 173,815 channel switches, 0 tuning errors, no resets |
| Remote ID reception and decoding (Wi-Fi Beacon, Open Drone ID v2) | Field-verified | DJI Avata, 5 GHz channel 149 (receiver-reported) |
| Detection without a valid position | Field-verified | 66 indoor receptions, no GPS fix, kept off the map |
| Real aircraft GPS positions | Field-verified, not yet ground-truthed | 163 receptions on the ground, motors running, ~1 m spread. Not yet compared with an independent GPS fix. No flight yet. |
| Raw capture and SQLite history, coverage and loss accounting | Field-verified | Real sessions captured, imported and rebuilt with identical results |
| CoT generation | Field-verified | Captured session replayed offline: 162 events matched the stored observations exactly |
| Authenticated TLS forwarding to a TAK Server | Field-verified | Mutual TLS with hostname verification; a separate listen-only client received the server's redistributed events |
| Aircraft and operator markers in iTAK | Field-verified | Both displayed in iTAK during the 2026-11-02 test |
| **LAST KNOWN** marker lifecycle (live → last known → live) | **Software only** | Not yet checked in iTAK |
| **Drone, operator and last-known map symbols** | **Software only** | Not yet checked in iTAK |

Known issues: one receiver stalled and dropped off USB during the first outdoor session (cause unknown); iTAK did not visibly retire markers when their CoT stale time passed, which is why LAST KNOWN exists. See the [technical journal](docs/DRONK-JOURNAL.md).

### LAST KNOWN and map symbols (not yet verified in iTAK)

- After 60 s with no new broadcast, DRONK sends one update on the same marker: the last real broadcast position, labelled `LAST KNOWN`, with the actual last-seen time and no implied movement. It is never refreshed as if current.
- The operator marker ages on its own broadcasts and never borrows the aircraft's position.
- Each report says whether the aircraft went quiet (`no_receptions`), the receiver lost coverage (`receiver_interrupted`) or monitoring stopped (`monitoring_stopped`).
- When broadcasts resume, the same markers go live again.
- Symbols: rotary-wing drone `a-u-A-M-H-Q` or fixed-wing drone `a-u-A-M-F-Q` from the broadcast UA type (otherwise `a-u-A`), operator `a-u-G`, last known as a grey map spot `b-m-p-s-m`. `--last-known-style same-type` keeps the live symbol and changes only the label.

## Quick start (demo, no hardware)

Needs JDK 17 and Python 3.11+.

```bash
bash tools/dronk/run-dronk.sh --demo
```

Open http://127.0.0.1:8765 and click **Start DRONK**. The demo runs two synthetic aircraft through the same parser, tracker and CoT generator, opens no devices and never forwards. For real receivers, CAPTURE and LIVE modes, see the [Command Center README](tools/dronk/README.md). For the receiver firmware, see [firmware/esp32-c5-receiver](firmware/esp32-c5-receiver/README.md).

## Privacy

Captures and the database live under `~/.local/state/dronk`, outside the repository. They contain aircraft serial numbers, positions and, when broadcast, operator positions. Never commit captures, databases, TAK certificates, passwords or real device identifiers. Test fixtures use synthetic identifiers.

## Background

DRONK started with a simple question: could an existing OUI-SPY drone detector report what it sees directly to a TAK Server? That proof of concept was called OUI-TAK, which is why the Gradle project and Kotlin packages still carry that name. From there the project moved to its own ESP32-C5 receiver and host software, and that became DRONK.

This repository is published as a source snapshot. Earlier development history is not included.
